# Kasuku Product Definition

## Product summary

Kasuku is an AI-powered contextual interpreter that helps visitors and Rwandans communicate naturally across language barriers during everyday real-world interactions.

Kasuku supports a continuous, two-way conversation between people who speak different languages. A user chooses a real-world context and a source and target language, then types or speaks. EjoChat interprets the message using the selected context and recent conversation history. The other person can respond in their own language, and Kasuku interprets the response in the opposite direction.

## Product principles

- Interpret the speaker's intended message naturally; do not mechanically substitute words.
- Preserve meaning, intent, tone, and politeness.
- Remain an interpreter, not a chatbot that answers the speaker.
- Make the interface simple enough for two people sharing one phone.
- Show translated text as the primary result; audio is an optional enhancement.
- Keep the conversation usable when microphone, text-to-speech, or upstream APIs fail.
- Prioritize a focused, reliable hackathon MVP over extra features.

## Intended users

- Visitors in Rwanda who need help with ordinary interactions.
- Rwandans communicating with visitors who do not share their language.
- Two people using a single mobile device in a face-to-face conversation.

## MVP contexts

1. Transport
2. Restaurant / Food
3. Hotel / Accommodation
4. Shopping / Market
5. General Conversation

## Initial languages

- Kinyarwanda
- English
- French
- Swahili

The MVP is intended to support interpretation between selected source and target languages from this set. Actual pair coverage must be confirmed against EjoChat capabilities before implementation.

## Core user journey

1. The user selects a communication context.
2. The user selects source and target languages.
3. The first speaker types or dictates a message.
4. Kasuku sends the message, context, language direction, and relevant recent history to a secure server endpoint.
5. EjoChat returns a natural interpretation of what the speaker wants communicated.
6. Kasuku displays the interpreted text immediately.
7. When applicable, the user may play Kinyarwanda audio generated by the C4IR/KiNLP TTS API.
8. The participants switch direction and continue the conversation, preserving useful recent context.

## MVP capabilities

- Context selection
- Source and target language selection
- Text input
- EjoChat-powered contextual interpretation
- Conversation history
- Two-way conversation
- Language/direction switching
- Speech-to-text
- Optional Kinyarwanda text-to-speech

## Required AI behavior

EjoChat is Kasuku's core language intelligence. It must:

- interpret naturally instead of word-for-word;
- preserve meaning, intent, tone, and politeness;
- use the selected communication context;
- use recent conversation history;
- resolve conversational references;
- translate what the speaker wants communicated; and
- never respond as an assistant to the content being interpreted.

Example:

> Previous — Visitor: “I need a moto to Kigali Heights.”
>
> Current — “Ask him how much it will cost.”

The interpretation must use history to infer that “him” refers to the moto driver and “it” refers to the trip to Kigali Heights. It must communicate the visitor's question rather than answer it.

## Reliability and experience requirements

- The interface must be mobile responsive, readable, and accessible.
- Loading, success, empty, and failure states must be clear.
- Translated text must render without waiting for text-to-speech.
- If speech recognition is unavailable or fails, typing must remain available.
- If TTS is unavailable, slow, or fails, translated text and conversation controls must continue working.
- API errors must be explained in plain language and allow retry without losing the conversation where practical.
- No credentials or secrets may be exposed to browser code or committed to Git.
- Every milestone must leave the repository in a working, reviewable state.

## Out of scope for the MVP

- Accounts or authentication
- Admin dashboard
- Payments
- Maps
- Persistent cloud conversation history
- Analytics dashboard
- Medical or emergency interpretation
- Unnecessary additional AI features

## MVP success criteria

The MVP succeeds when two people sharing a mobile device can select one of the supported contexts and language directions, exchange a multi-turn conversation through typed or spoken input, receive context-aware natural interpretations, reverse the language direction, and continue despite microphone or TTS failure. Credentials remain server-side and the deployed experience is suitable for a hackathon demonstration.
